# FM_Ilan_GridEA

اکسپرت جدید: موتور اجرای گرید/مارتینگل + بیسیک بریک‌ایون از `Ilan1_MartingaleGrid_MT5` گرفته شده،
و موتور تشخیص ورود آن به‌جای فقط دو حالت قدیمی، حالا از طریق `InpEntryMode` می‌تواند کل
موتور استراتژی پروژه FM-Indicator را هم صدا بزند — بدون اینکه حتی یک خط از منطق تحلیلی
آن پروژه بازنویسی شده باشد (فایل‌های `Analysis.mqh` / `StrategyRegistry.mqh` /
`ParityDecision.mqh` عیناً همان‌هایی هستند که `FM_EA.mq5` خودِ آن ریپو استفاده می‌کند).

## نصب

کپی کنید داخل پوشه دیتای متاتریدر:

```
MQL5/Experts/FM_Ilan_GridEA.mq5
MQL5/Include/FM/*.mqh          (اگر از قبل ندارید — همان پوشه‌ی پروژه FM-Indicator)
```

اگر ریپوی `FM-Indicator` را از قبل کامپایل کرده‌اید، پوشه `Include/FM` را از این پکیج نیاز ندارید؛
فقط EA جدید کافی است.

حساب باید **Hedging** باشد (دقیقاً مثل Ilan1 اصلی).

## InpEntryMode — ۹ حالت، دسته‌بندی‌شده

| مقدار | توضیح |
|---|---|
| `ENTRY_MANUAL` | جهت دستی با `InpManualDirection` (بدون تغییر نسبت به نسخه اصلی) |
| `ENTRY_MA3_CROSS` | هم‌راستایی ۳ میانگین متحرک (بدون تغییر نسبت به نسخه اصلی) |
| `ENTRY_FM_AUTO` | مسابقه AUTO بین همه استراتژی‌های FM (همان منطق `STRAT_MODE_AUTO` خود پروژه) |
| `ENTRY_FM_PULLBACK` | فقط ستاپ Trend Pullback (H1/H2/L1/L2) |
| `ENTRY_FM_BREAKOUT` | فقط ستاپ Breakout / Follow-Through |
| `ENTRY_FM_REVERSAL` | فقط ستاپ Major Trend Reversal (MTR) |
| `ENTRY_FM_DOUBLE` | فقط ستاپ Double Top/Bottom |
| `ENTRY_FM_FADE` | فقط Measured-Move Fade (هسته اصلی اندیکاتور FM) |
| `ENTRY_FM_FAILED_BO` | فقط Failed-Breakout Fade |

هر کدام از حالت‌های `ENTRY_FM_*` که انتخاب شود:
1. روی هر کندل بسته‌شده، `CFMAnalysis::Update` (همان pipeline کامل: ATR → Swing → Breakout →
   Pullback → Reversal → MeasuredMove → GeneralSetups → Decision) اجرا می‌شود.
2. `CStrategyRegistry` و `CParityBuilder` (دقیقاً همان کلاس‌هایی که در `FM_EA.mq5` هست) بهترین
   ستاپ را انتخاب می‌کنند — در حالت AUTO با همان امتیازدهی trend/RR/provisional.
3. وتوهای ساختاری (`BARBWIRE` / `MID_RANGE` / `CONFLICT` / `NO_EDGE` / `TRAP_REPEAT`) با
   `InpApplyStructuralVeto` قابل روشن/خاموش‌کردن است.
4. جهت نهایی (خرید/فروش) به موتور گرید/مارتینگل داده می‌شود که دقیقاً مثل نسخه اصلی Ilan1
   پوزیشن اول را باز می‌کند و سطوح گرید، بریک‌ایون بیسکت، و SL انتهای گرید را مدیریت می‌کند.

پارامترهای تحلیلی خودِ موتور FM (سوئینگ، ATR، تلورانس‌ها، فیلترهای Breakout/Reversal/Pullback و...)
همگی زیر گروه **"FM-Indicator Analysis Parameters"** در پنجره Inputs قرار دارند (عیناً از
`Include/FM/Inputs.mqh` — تغییری در نام یا مقدار پیش‌فرضشان داده نشده تا با پریست‌های
موجود پروژه هم سازگار بماند).

## چه چیزی از Ilan1 اصلی دست‌نخورده مانده

- منطق گرید کامل (`PlaceFullGrid` / `EnsureNextPending`)
- بریک‌ایون بیسکت با احتساب کمیسیون/سواپ/اسپرد
- SL انتهای گرید (`GridBoundaryPrice`)
- TP پوزیشن اول
- فیلتر اسپرد، فیلتر ADR/کندل بزرگ، انتظار برای بسته‌شدن کندل

## بهبود / بهینه‌سازی‌های اضافه‌شده روی موتور گرید

1. **`PlaceFullGrid` دیگر هر تیک اسکن کامل نمی‌کند** — وقتی همه سطوح گرید از قبل پندینگ
   دارند (حالت پایدار معمول)، تابع فوراً برمی‌گردد به‌جای اینکه هر ثانیه روی همه سطوح
   `PendingExistsNear` صدا بزند.
2. **کش روزانه ADR** — قبلاً هر تیک (هر ثانیه با `InpProcessIntervalSec=1`) کندل‌های روزانه
   دوباره خوانده و جمع می‌شدند؛ حالا فقط یک‌بار در روز محاسبه و کش می‌شود.
3. **یک ردیاب کندل جدید مشترک** — `IsTradeAllowed` قبلاً یک `static` جدا برای تشخیص کندل
   جدید داشت که با ردیاب سراسری `IsNewBar()` تکراری بود؛ الان `OnTick` یک‌بار `isNewBar`
   را محاسبه می‌کند و به هر دو جا پاس می‌دهد.
4. **کیل‌سوییچ ضرر بیسکت (جدید، پیش‌فرض خاموش)** — `InpMaxBasketLossMoney`: اگر ضرر
   شناور کل بیسکت (با احتساب کمیسیون/سواپ) از این مقدار (به ارز حساب) بیشتر شود، کل
   بیسکت بسته و گرید ریست می‌شود. برای مارتینگل/گرید که در روند قوی می‌تواند خطر جدی
   داشته باشد، یک لایه محافظتی اضافه است — پیش‌فرض `0` (خاموش) تا رفتار قبلی تغییر نکند.
5. حذف متغیر مرده `g_last_pos_count` (تنظیم می‌شد ولی هیچ‌جا خوانده نمی‌شد).

## نکته مهم

موتور FM فقط **سیگنال جهت** تولید می‌کند (خرید/فروش برای باز کردن پوزیشن اول بیسکت).
اجرای معامله، حجم، گرید، بریک‌ایون و مدیریت ریسک بیسکت همگی کار همان موتور Ilan1 است —
موتور اجرای خودِ FM (`ExecutionEngine.mqh` / `PositionManager.mqh`) در این اکسپرت
استفاده *نشده* تا با سیستم گرید تداخل نکند.

پیشنهاد: قبل از اجرای روی حساب واقعی، حتماً با هر یک از حالت‌های `ENTRY_FM_*` روی
Strategy Tester (مود Every tick یا Real ticks) بک‌تست بگیرید — مخصوصاً چون ترکیب
مارتینگل + سیگنال‌های FM هنوز جایی تست نشده و پارامترهای گرید (`InpPipStepString`,
`InpMaxTrades`, `InpLotExponent`) باید متناسب با نوسان نمادی که استفاده می‌کنید تنظیم شود.
